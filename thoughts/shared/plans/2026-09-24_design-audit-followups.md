# Design audit follow-ups

## Goal

Resolve the five local Chrome design-audit findings without changing student-data handling, diagnosis requirements, or the learning content.

## Non-goals

- No backend, login, analytics, microphone, upload, or deployment work.
- No change to vocabulary scheduling, accepted answers, or export/import formats.
- No redesign of desktop navigation beyond the mobile information hierarchy.

## Acceptance criteria

- At 390 px, the welcome hint is fully readable and the full accessible label remains available.
- At 390 px, revealing a vocabulary card keeps both rating choices visible in the first viewport.
- A learner who has not completed diagnosis sees one clear level-test CTA on Start.
- The unavailable mixed quiz is visibly secondary to usable vocabulary practice.
- The mobile navigation consumes less vertical space while retaining all eight named destinations, active state, and approximately 44 px touch targets.
- Desktop layout remains readable, and neither width has horizontal overflow.

## Files to change

- `index.html` — small structural and state-label changes for home and vocabulary entry.
- `src/styles/tailwind.css` — responsive layout and visual-priority rules.
- `tests/mobile-polish.spec.js` — focused Playwright regression coverage.
- `dist/tailwind.css` and `sw.js` — generated by `npm run build:app`.

## Test plan

1. Add one focused Playwright expectation for one finding and run `npx playwright test tests/mobile-polish.spec.js --browser chromium`; it must fail first.
2. Make only the required production change and rerun the same command until green.
3. Repeat the red-green cycle for each remaining finding.
4. Run `npm run build:app`, `npm run test:all`, and `git diff --check`.
5. Visually inspect Start, Gloser, and one reveal/rate flow in Chrome at 390 px and about 1440 px.

## Steps

1. Make the narrow welcome placeholder compact without changing its accessible label.
2. Compact the active mobile vocabulary view enough that the rating buttons begin above the viewport edge.
3. Use the existing diagnosis panel as the single level-test CTA and remove the duplicate home CTA for an uncompleted diagnosis.
4. Make the locked mixed-quiz launcher compact and secondary while retaining its explanatory status.
5. Compact the mobile navigation with a progressive-disclosure control that retains direct access to every destination.
6. Regenerate app assets, run regressions, perform the visual check, then close and sync each Bead.
