# Brainmap v1 implementation plan

## Goal
Render a local-first A0/A1 brainmap from the stable learning catalog and current progress without replacing the existing category-based practice flow.

## Non-goals
- No adaptive quiz selection, streaks, focus quiz, or A2/B1/B2 content.
- No cloud sync, login, analytics, or new student data.
- No removal of the existing vocabulary category brainmap buttons.

## Acceptance criteria
- Current catalog skills render as visible microskill nodes, including unattempted gray nodes.
- Skill colors follow the contract: gray, red, yellow, green, blue/gold.
- Vocabulary areas show conservative direction-aware strength and expose direction split when the two directions differ by at least 2.
- Unknown imported skill/word IDs are retained in local progress but are not rendered.
- Group colors cannot exceed yellow when an attempted child is red.
- The brainmap remains keyboard accessible and existing category buttons still launch vocabulary practice.
- All brainmap logic has deterministic tests.

## Files to change
- `index.html` - pure brainmap model helpers, microskill/area rendering, existing category rendering compatibility.
- `tests/brainmap-progress.spec.js` - model and UI regression tests.
- `package.json` - `test:brainmap` and `test:all` registration.
- `src/styles/tailwind.css` - compact responsive microskill/status presentation if needed.
- `dist/tailwind.css` - rebuilt CSS artifact if source styles change.

## Steps
1. Add failing tests for thresholds, conservative vocabulary direction handling, unknown IDs, and group cap.
2. Implement pure brainmap node/status helpers and verify the focused tests.
3. Add microskill and vocabulary-area sections to the existing Brainmap page while retaining legacy category buttons.
4. Add UI tests for rendering, keyboard access, and unknown-node filtering.
5. Run brainmap, catalog, progress, import/export, PWA smoke, content, Tailwind, and diff checks.
