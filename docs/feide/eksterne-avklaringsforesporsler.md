Hvis EØS-only er et krav, stans Vercel/Supabase-produksjonsløpet og vurder alternativer. | Besvart for staging; produksjons-/overføringsaksept gjenstår. |
| Intern sikkerhets-/personvernkontakt og stedfortreder | Navngi ansvarlig person og en praktisk reserve; rolle kan samles hos én person i oppstartsfasen, men dette skal beskrives som én-operatør-avvik. | Eierens navn/roller og sikker kontaktkanal mangler. |
| Tilgangsadministratorer | Navngi personlige admin-kontoer for Vercel, Supabase, GitHub, Sikt og DNS; slå på MFA; fjern delte kontoer; dater kontroll. | Vercel og Supabase medlemslister er kontrollert; full tilgangs-/tokeninventar og reserveadministrator gjenstår. |
| Lagring av læringsutfall | Forslag: slett ved skoleårets slutt eller senest 90 dager etter klasse-/avtaleslutt; slett tidligere når formålet opphører. Skoleeier avgjør endelig regel per avtale. | Intern standard er ikke vedtatt; skoleeiers endelige frist må inn i avtalen. |
| Sikkerhetsjournal | Fastsett separat kort frist med formål, tilgang og slettemetode; ikke la læringshistorikk bli liggende i journalen. | Konkret frist, tilgangsregel og automatisk sletting må vedtas og verifiseres. |
| Pilotberedskap | Ingen ekte elevdata eller Feide-identiteter før DBA, skoleeiers instruks/DPIA-beslutning, logger/retensjon, backup/restore, MFA og Feide-test er signert. | Besvart som arbeidslås; gjenåpning krever ny uttrykkelig produkteierbeslutning og skoleeiers skriftlige godkjenning. |

## Skoleeier – beslutninger per kunde

Skoleeier må dokumentere behandlingsansvar, formål/nødvendighet, behandlingsgrunnlag, elev-/lærergrupper, DPIA-behov, informasjon til elever/foresatte, datakategorier/attributter, retensjon, godkjent hosting/overføring, backup, innsyn/eksport/sletting, hendelsesvarsling og hvem som godkjenner skole-/klassemedlemskap. Oversikt AS kan levere teknisk faktagrunnlag, men skal ikke fylle inn skoleeiers beslutninger på deres vegne.
