Portalen er kontrollert: konfidensiell OIDC-klient, Feides testbrukere er aktivert, tjenesteleverandør-brukere/eduGAIN/OpenIdP er deaktivert. «Krev alltid brukerinteraksjon» er ikke valgt. Navn (userinfo-name) med begrunnelse er lagret. Ingen vertsorganisasjon har aktiveringstilgang.

Nettverksobservasjonen viser:
1. Appens /auth/login svarer HTTP 303 til Feides /oauth/authorization med korrekt client ID og eksakt redirect URI, response_type=code, response_mode=form_post, scope «openid userinfo-name», PKCE S256, state og nonce. Forespørselen har ikke login_hint, authselection, login_started, prompt eller acr_values.
2. Feides /oauth/authorization svarer HTTP 302 til /accountchooser med returnTo og clientid.
3. Feides /accountchooser svarer HTTP 302 tilbake til /oauth/authorization og legger til login_started og authselection=other|feidetest. Ingen interaktiv kontovelger vises i dette forsøket.
4. Feides /oauth/authorization svarer da HTTP 400 med feilen over.

Det sanitiserte sporet inneholder disse dokumentnavigasjonene og sluttstatusen, ikke en komplett nettverkslogg. Vi deler ikke den komplette forespørselsadressen, returnTo, headere, cookies eller verdiene til state/nonce/PKCE.

Feides detaljdokumentasjon beskriver at autoriserte attributtgruppenavn kan brukes som scopes, og userinfo-name er lagret på tjenesten.
