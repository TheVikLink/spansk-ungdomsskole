# Avklaringsregister for Feide og produksjonssetting

Sist revidert: 3. oktober 2026. Dette registeret konkretiserer hvert forhold som ikke kunne fastslås ved publisering av leverandørerklæringen. «Avklart» betyr at fakta er dokumentert; det betyr ikke automatisk at risiko eller kontraktskrav er godkjent. Elevdata skal ikke legges inn før alle stoppunktene nedenfor er lukket skriftlig.

## Svar som kan brukes nå

- **EØS-only behandling:** Nei, ikke dokumentert for valgt Vercel/Supabase-oppsett. Stockholm er primærregion, ikke fullstendig behandlingsgrense.
- **Aktivert og produksjonstestet Feide:** Nei, publisert tjenesteerklæring er ikke bevis på ferdig klientkonfigurasjon eller vellykket ekte innlogging.
- **Produksjonsklar database/app:** Nei, prosjekt-/miljøhemmeligheter, produksjonskonfigurasjon og driftsverifikasjon må bekreftes. Ikke bruk ekte elevdata.
- **DBA, DPIA og lovlig grunnlag:** Ikke ferdig. DBA må signeres av riktige parter; skoleeier fastsetter grunnlag og DPIA-behov.
- **Uavhengig sertifisering:** Nei. ASVS-tabellen er intern kartlegging. Leverandørenes sertifikater gjelder deres avgrensede kontrollomfang.
- **Backup/restore:** Leverandørene beskriver egne backupfunksjoner; dette er ikke en gjennomført restore av Spansk123. Test restore i isolert staging og dokumenter mål og resultat.

## Rekkefølge for lukking

1. **Leverandørvalget er tatt:** Vercel + Supabase godtas, også med kjent global behandling. Produkteier må fortsatt bekrefte hvem som har admin- og personvernansvar i Oversikt AS.
2. Oversikt henter konto-/prosjektspesifikke bevis fra Vercel, Supabase, Sikt og DNS; fyller oppdatert dataflyt, logger, tilgangsmatrise og underleverandørkart.
3. Skoleeier vurderer formål, behandlingsgrunnlag, rollefordeling, retensjon, DPIA og elevinformasjon.
4. Partene fyller ut og signerer DBA med bilag; avtal bistand, hendelser, revisjon, overføringer, backup og avslutning.
5. Oversikt setter opp secrets, prod/staging-separasjon, scheduler, varsling, logging, backup/restore, MFA og minsteprivilegium; kjør bare syntetiske data.
6. Test Feide mot testbruker, korrekt issuer/claims, MFA/ACR, logout, konto-/skoleisolering, innsyn/sletting og gjenoppretting. Oppdater leverandørerklæring i portalen når faktiske forhold endres.
7. Skoleeier gir en skriftlig pilotgodkjenning med avgrenset omfang før noen elevkonto eller reelle læringsresultater opprettes.
